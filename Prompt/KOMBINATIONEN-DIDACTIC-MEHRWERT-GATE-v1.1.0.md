# Kombinationen — Lean Didactic Gate v1.1.0

**Status:** User-approved prospective replacement for `KOMBINATIONEN-DIDACTIC-MEHRWERT-GATE-v1.0.0.md` operational review requirements (2026-11-02). Applies to lexical workstreams at the next safe editable boundary. Full existing lexical source and typed-provenance policy still applies, no UI redesign.

1. **Meaning first.** Keep a learner-facing Kombination only when it is natural, sense-compatible, translated DE/FA/EN as required, honest about source/curated origin, and teaches something beyond existing headword, example or related term. Accept productive case/preposition, collocation, reusable context, idiom, contrast or register. A useful phrase can overlap an example; overlap is a **review signal**, not an automatic error.
2. **No quantity target.** One, many or zero useful combinations are valid. Use `CLOSED_NO_FORCE` + machine-recognizable nonempty reason such as `NO_ADDITIONAL_TEACHING_VALUE` for no genuinely useful new combination. No fabricated fillers.
3. **Short evidence, no essays.** For ordinary obvious retained items, record a stable `teaching_delta` reason code (`REKTION`, `COLLOCATION`, `PATTERN`, `FIXED_PHRASE`, `CONTRAST`, `CONTEXT`, `REGISTER`), link it to existing card ID, version/hash and real source/curated provenance. Detailed prose is necessary only for ambiguous/unusual/high-risk decisions; do not demand duplicate manual notes if existing structured evidence supplies these fields.
4. **Advisory scanner stays advisory.** Run the normal scanner on exact current source, but a short phrase, exact example span or close variant **alone** is not a defect. Do not require separate manual KEEP/CORRECT/REMOVE for every LOW/INFO alert. Group MEDIUM/LOW/INFO matching flags under `STAGE4-RISK-BASED-ACCEPTANCE-POLICY-v1.0.1.json` only with exact affected IDs, typed family trigger, required source hash, independent representative review and adversarial check. Every CRITICAL/HIGH substantive risk is still reviewed **individually**.
5. **One pass + one challenge.** Stage 3 checks same-card meaning/examples/combinations while enriching. Stage 4 performs *independent* risk-targeted language challenge once, not a duplicate authoring pass. Recheck changed IDs and impacted dependencies, or systemic defects. No routine historic re-audit just because this overlay changed.
6. **Outputs unchanged.** Keep backend type/provenance and **one learner-visible section `Kombinationen`**; no automatic deletion/mass append; Stage5 exact projection, Stage6 CURRENT native browser, Stage7 packaging and LOCKED/source protections remain separate and mandatory.

**Specific supersession:** Paragraph 7 of the v1.0.0 didactic policy (every advisory flag needs its own outcome and old `--gate` blocks) and paragraph 9 (global mandatory retro-audit) are no longer mandatory *operating steps* for new eligible work. The old portable scanner and v1.0.0 materials are historical and not modified here; any unmodified older executable still enforces its old contract and must not be presented as supporting v1.1.0 until adapted and proven.

Canonical Stage 3 operational reference: `Prompt/LEAN-STAGE3-4-OPERATING-MODE-v1.0.0.md`; canonical Stage4 acceptance: `STAGE4-RISK-BASED-ACCEPTANCE-POLICY-v1.0.1.json`. This is a **replacement** of overlapping workflow text, not another layer of review.
